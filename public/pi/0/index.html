Pinto Improvements

PI-0: Fix the PINTO:USDC Multi Flow Pump and Update Multi Flow Pump Cap Parameters

Executed on November 20, 2024 at 01:31 UTC.

Summary

  1. Multi Flow Pump Bug: Fix a bug in the Multi Flow Pump that caused the Pump to return incorrect data for the PINTO:USDC liquidity pool.
  1. Pump Parameters: Update the Wells on the Minting Whitelist to use a new Multi Flow Pump with more forgiving LP token supply and exchange rate change caps of 25% per block (2-second cap interval) in order to allow the Flood to return the price to the value target in instances of greater volatility.
  1. Deposit Metadata: Update the Metadata Facet to return the correct metadata.

Problems

1. Multi Flow Pump Bug

The implementation of the Multi Flow Pump resulted in the tryCalcLpTokenSupply helper returning MAX_UINT256_SQRT (the integer square root of uint256.max) when the Newtonian estimation in Stable2’s calcLpTokenSupply failed to converge at high prices, causing the function to revert. Using this failure value in LP token supply capping produced incorrect reserve data and excessive minting.

2. Pump Parameters

During the Flood, the Well reserves hit the LP token supply and exchange rate caps. Because it took ~2 Seasons for the Pump values to catch up to the Pinto price, the protocol would mint more than it should’ve during the Flood.

3. Deposit Metadata

The ERC-1155 Deposit token was erroneously named "Beanstalk Silo Deposits".

Solutions

1. Multi Flow Pump Bug

Upgrade the _capLpTokenSupply function in Multi Flow Pump to skip LP token supply capping if calculating the LP token supply from either the previous or current reserves fails, while continuing to apply exchange-rate capping to the current reserves.

2. Pump Parameters

Upgrade the whitelisted Wells to a new Multi Flow Pump with more forgiving LP token supply and exchange rate change caps of 25% per block (previously set to approximately 0.493862% and 0.083160%, respectively), enabling the Flood to return the Pinto price to its value target in the instance of greater upside price volatility.

3. Deposit Metadata

Update the Metadata Facet to rename the ERC-1155 Deposit token from "Beanstalk Silo Deposits" to "Pinto Silo Deposits" and update its description and trait labels to use Pinto terminology.

Rationale

1. Multi Flow Pump Bug

The Stable2 Well Function uses Newtonian estimations to perform complex calculations on-chain in an efficient fashion. The further away from the value target, the greater the chance that the Newtonian estimation fails to converge, in which case the function reverts. In the instance of a reversion, it is better for the _capLpTokenSupply function in Multi Flow Pump to skip LP token supply capping when either calculation fails because MAX_UINT256_SQRT is an extremely high value which can lead to the protocol overminting Pinto. The Pump continues using the current reserve values, subject to exchange-rate capping.

2. Pump Parameters

The initial caps were designed to mitigate inter-block MEV on Ethereum, where control of consecutive blocks can enable oracle manipulation. On Base, there is no MEV performed by the sequencer, and so the risk of setting the parameters capping changes too high is almost non-existent. The Multi Flow Pump’s initial conservative caps limited how quickly its reserve values could respond to market changes. During a Flood with significant upward price volatility, this lag reduced the effectiveness of the Flood in returning the Pinto price to its value target. The higher caps allow the Pump to respond more quickly while retaining limits on changes in LP token supply and exchange rates.

3. Deposit Metadata

The Deposit token metadata should identify Pinto so that wallets and interfaces display the correct protocol name.
